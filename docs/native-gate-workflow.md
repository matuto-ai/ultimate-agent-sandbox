# Native artifacts Gate workflow

This opt-in source composition consumes existing native, Gate, quota and target
owners. It does not add a Participant Gate tool, capability or target-binding
packet. The ordinary `uas_review` submission is a proposal, never target authority.

## Existing submission, trusted preparation

`RunReview.submit` validates its envelope and original operation receipt before
any preparation. After its existing exact implementer/Actor/Participant checks,
`NativeReviewHost` invokes the configured `NativeGateWorkflow`. A fixed child
operation in the same Room ledger binds the entire original command to its prior
candidate binding, source and Run/control revision. Replaying a changed command
conflicts before another effect. This receipt is not freshness authority.

The trusted owner rechecks original native kernel custody, canonical attachment,
source and Run, then uses `GateHub.bind_target` and the existing audited Broker to
verify the exact candidate and perform its compare-and-swap. Required mechanical
submission Gates use stable child IDs and canonical evaluator reducers. Unknown
binding/evaluation results are not retried under new IDs. An exact terminal
submission returns its existing receipt without new preparation.

Native receipt reads and success-capable intent/result transactions use local
lifecycle → Git history → Room order. Provider/helper work is outside these locks.
A failed native fence feeds the existing immutable ERROR/quarantine path without
success-only callbacks re-entering lifecycle from a Room transaction. Cleanup can
record original owned facts after revocation; it cannot turn an error into a pass.
Durable external Gate refresh is followed by a new state read that must still match
the original Run scope and, for completion, exact review row.

## Actual optional profile

Installation may select `gate_manifest` only with the paired existing Git profile
and Git Broker references. The manifest pins artifacts-only static helper payload
and trusted host materializer binaries; no executable, package or credential is
created by selection. See `native-artifacts-resources.md` for the exact schema.

Root provisioning creates the quota-charged Supervisor scratch, private journals
and fixed endpoint directory. Only the trusted Supervisor child receives the
helper supplementary group. That child creates/listens the socket itself, checks
its ownership/mode and exact stock SELinux file label; absence fails closed rather
than changing policy. The same selected Gate mount-profile object is consumed by
both native recipes and the later actual resource owner.

After real Run/reviewer attachment, the session assembles `NativeGateResources`,
`NativeGateOperations` and this workflow before entering the existing driver.
The operational service yields an original helper channel and held process proof
through `GateOffer`; it never supplies a passed verdict. Root quota observation
uses the existing bounded root channel, fixed current project/instance and all
canonical outstanding/quarantined reservations. No quota ledger is duplicated.
The snapshot promises current conservative capacity, not immunity to later Room
usage; hard quota and ordinary error/quarantine handling remain mandatory.

## Explicit limits

This profile implements artifacts only. Command/diff profiles are separate and
fail explicitly if required; typed identity attestations and diff declarations
have no new native transport. Mechanical Gates required only for completion are
not eagerly evaluated at submission: their first trusted trigger remains a later
integration seam. No early failed evaluation is manufactured for them.

Git successor projection, authenticated human hosting/Manager dispatch, real
prepared-image/helper execution, provider accounts and full GitHub lifecycle
qualification remain separate. Controlled tests exercise actual canonical reducers
and authority/cleanup transitions with native boundaries mocked. They do not prove
Landlock, seccomp, SELinux communication, actual quota enforcement or live GitHub
completion. Production startup remains disabled by default.

The explicit full source inventory is126 files (artifacts130, command133); the
fixed file cap is136, each file remains <=256KiB and the aggregate <=3MiB. No
runtime repository discovery or caller-selected staging path is introduced.
