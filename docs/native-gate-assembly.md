# Concrete artifacts Gate assembly

`NativeGateOperations(host, resources)` requires the exact native review host,
its concrete `NativeGateResources`, shared Supervisor, Room/instance and fixed
Engine owner. It constructs the existing `ArtifactTargets` using canonical
source rechecks and the resource owner's real quota callback. A fixed factory
constructs `GateHelperLaunch` with the same admitted Workstation, endpoint,
lease and SHA-256 evaluation journal name. No operator callback or argv is
accepted. The returned `.control` is consumed by `NativeGateWorkflow`.

Only artifacts has operational resources in this increment. Generic local
transport support for command/diff does not qualify or enable those profiles.

Native Pi/Claude recipes accept an optional generated Gate mount profile only
alongside the exact Git profile. Its two readonly destinations are precisely
`/uas/gate-targets` and `/uas/gate`; all prior thirteen mounts remain verified.
Room, instance, container, image, mapping, digest and mount roles are bound.
There is no arbitrary `/uas` or `/opt` prefix exemption. Default recipes retain
their prior identity and mount validation.

Preparation/launch use the active workflow's full preparation/readset fence,
then release lifecycle/Git locks before effects. An attached idle workflow is
not a fallback authorization. Canonical final consumption still rechecks.

Closing this owner releases held offer/launch descriptors and journal handles,
attempting every owned close. It neither deletes evidence/targets nor claims
helper exit or quota cleanup. Root resource teardown and the existing canonical
Gate cleanup/quarantine rules remain authoritative.
