# Opt-in controlled Git qualification wiring

The existing native selection can additionally name **both** `git_manifest` and
`git_broker_manifest` references (canonical path plus selected SHA256), or neither.
No default image, SSH key, account or new credential is created. The Git resource
profile verifies the separately prepared image, fixed runtime replacement and
primary checkout projection; an installation declaration alone is not admission.

The public Git Broker manifest contains version 1, `ssh_executable`, `ssh_sha256`
and one `{actor_id, key_path, known_hosts_path}` row for each configured native
Participant Actor. These are existing private-file references, not secret values.
The parser uses the existing `GitTransportConfig`/`SshActorCredential` contract.
Check-only reads public manifests only. Execute rechecks canonical private regular
single-link file metadata and exclusion from Workstation Project/runtime mounts and the fixed `/run/uas-native` public projection tree;
the canonical Broker opens and revalidates credentials immediately before use.
SSH executable integrity remains separate from credential contents.

The root wrapper runs the fixed `uas.git_service` entrypoint as the existing
Broker UID, with a separate channel and private audit sibling. Spawn intent and
actual `Popen` custody precede startup bytes. All three fixed module roles use
`cwd=/` plus the exact trusted code root, not the invoking project directory. The trusted child performs the
existing `GitBrokerClient` kernel-peer handshake; ReadBroker is not substituted.
An uncertain SSH/Git Broker is neither killed to force success nor retried. Its
exact audit and root-owned evidence remain retained until explicit reconciliation.

The authenticated host constructs the concrete `NativeGitOperations` from the
same Room ledger, Git provenance, canonical active Run, allocator/source and exact
held Pi/Claude roots. The finite session loop consumes its actual request listener.
Original participant kernel lineage supplies the Actor; neither the human request
nor mutable Git output chooses authorship. Only the fixed admitted native mount
profile is accepted by both recipes; arbitrary extra mounts remain rejected.

This first profile provides the primary worktree projection. A successor's new
retained-predecessor worktree does not become a mount root merely because its
parent directory is mounted. Git-enabled successor transition therefore refuses
before retiring the completed predecessor until an exact successor projection
exists. No primary fallback or mount-propagation exception is granted.

Gate evaluator resources, authenticated human transport, selected image execution,
model accounts and real GitHub lifecycle evidence remain distinct prerequisites.
Controlled source tests do not prove native Git, SSH contact, a provider write or
end-to-end completion. Production startup remains disabled.
