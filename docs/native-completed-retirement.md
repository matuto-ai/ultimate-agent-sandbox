# Completed native Run retirement and first Pi reuse

This is a trusted-host source path, not a new authentication mechanism or a
qualification result. An actual `NativeRunAdmission`, authenticated `HumanSession`
with stop authority, and the exact held reviewer recruitment owner are required.
Installation JSON, a stored receipt, or a PID cannot construct this authority.

`retire_completed(operation_id, run_id, generation, expected_revision,
session=..., reviewer=...)` applies only to an already CLOSED, completed Run.
It pins the canonical assigned context targets, original completion evidence and
control revision before requesting any native effect. It increments the control
revision once and records an intent in the existing Room ledger. It never reopens
the Run or changes its generation, completed outcome, policy, checkout or merge
proof. A changed command under the same operation ID is a conflict.

Every assigned target needs its actual retained native owner, including targets
whose Hub readiness is LOST. Pi retirement proves the exact retained Pi task;
Claude retirement proves the exact retained SDK host, native process and helper.
Canonical revocation acknowledgement plus duplicated-pidfd exit observations are
required. Missing owners, uncertain revocation or partial exits retain the pending
intent and custody; they are not VERIFIED. Retrying uses the same primitive and
observes unknown outcomes rather than issuing another stop. Successful receipt
replay still requires current human authorization but not liveness of dead tasks.

The host lacks a checkout writer-quiescence grant. Its explicit result is
`RETAINED / NATIVE_CHECKOUT_WRITER_QUIESCENCE_UNAVAILABLE`. Task exit does not prove
arbitrary tool descendants stopped, so the old worktree cannot be reused, removed
or declared quiescent. The root allocator may create a different unique worktree
only while the exact predecessor slot remains active and ready in canonical
allocator state. It preserves dirty predecessor data and refuses primary-path
fallback if that predecessor changed or disappeared.

The bounded qualification adapter supports the first Pi context reuse only:
context generation 1 to 2, for a distinct newly reserved Run. The existing context
request/success reducers receive the genuine human Origin. Reset is requested
before root allocation. The old exact retirement registry must still prove all
old task exits and the unchanged completed receipt. A new native Pi scope, empty
session and distinct session/runtime identities must be current before the
context generation advances; the subsequent Hub admission uses the old epoch
plus one. Initial admission retains its existing path.

The launcher retains old custody separately from the new attempted target. An
uncertain launch never clears the attempt marker to force another process.
After fresh preparation or ADMIT uncertainty, this API does not automatically
resume every phase: existing exact STATUS reconciliation and retained evidence
remain necessary. This is not general repeated lifecycle support.

Local evidence is controlled canonical-ledger/typed-owner testing under effect
guards. Actual native execution, provider accounts, authenticated human hosting
and the independent #62/#79 qualification prerequisites remain separate. This
change creates no credentials and does not enable production startup.

For the successor reviewer, `recruit(..., reset_from=previous)` internally finds
the same completed-retirement registry and reuses its exact retained Claude exit
proof. It does not recapture a dead process or resend revocation. The canonical
old attachment, incarnation, Actor and context must still match the pinned target;
LOST is allowed only for that proven-retired owner, never a replacement. The usual
live-reviewer reset path remains unchanged. New Claude fresh HOME/session/helper
proof and epoch advancement still precede admission through the existing reset
flow.
