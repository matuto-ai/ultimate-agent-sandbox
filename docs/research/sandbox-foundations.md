# Research: Inventory reusable foundations from the existing sandboxes

## Summary
The best foundations are split across all three codebases. Reuse Herdr Sandbox directly for project identity validation, path-safe project resolution, and the external Forge Broker with audit; adapt Ai Agents Sandbox’s direct-repo mount option and mount layout ideas so worktrees are optional; adapt only Parley’s path-safe filesystem helpers and durable event/dispatch store, not its current execution model.

The main incompatible assumption across both Ai Agents Sandbox and Herdr Sandbox is that a managed worktree is the normal execution unit. For this spike, the smallest viable direction is a single trusted workstation container with explicit project mount records, pluggable checkout mode (`direct` vs `managed`), Herdr-style brokered host integrations, and Parley-style durable event/session state.

## Findings
1. **Reuse directly: Herdr’s external Forge Broker and audit trail are already the right trust-boundary shape.** The broker listens on a Unix socket, enforces per-project policy before invoking `gh`/`tea`, runs host CLIs in a temp HOME/XDG sandbox, caps request/output sizes, and writes audit records; the tests explicitly check write gating, provider mismatch handling, and that secrets do not leak into the audit log. This matches the target “external Forge Broker” better than anything else in the mounted sources. (`/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/forge/broker.go:22-66, 120-236`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/forge/broker_test.go:20-118, 170-259`)

2. **Reuse directly: Herdr’s project ID and path-resolution rules are good foundations for three explicit project mounts and path safety.** `ValidateProjectID` rejects traversal and requires normalized slash-separated relative IDs; `projects.Resolve` canonicalizes roots with `EvalSymlinks`, rejects escapes outside the repo root, and requires a real `.git`; tests cover traversal and symlink escape rejection. That is the right base for a fixed three-mount registry, with discovery removed. (`/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/config/config.go:14-24, 118-157`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/projects/projects.go:14-90`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/config/config_test.go:56-68`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/projects/projects_test.go:45-54`)

3. **Reuse directly: Herdr’s identity bundle checks are stricter than the shell-based predecessor and fit the target identities requirement.** The control binary validates that each configured identity expands to an absolute directory, contains a regular `gitconfig`, and has direct `user.name`/`user.email` values; SSH config is optional but, once present, requires a regular `known_hosts`. The container launcher then mounts each identity bundle read-only at `/run/git-identities/<agent>`. This is the best existing identity foundation. (`/project/reference/herdr-sandbox-src-copy-28-07-2026/cmd/herdr-sandbox/main.go:612-718, 781-799`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/bin/llm:147-181`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/cmd/herdr-sandbox/main_test.go:14-92`)

4. **Adapt: Herdr’s long-lived session control is the strongest control-plane starting point, but its session record model is too worktree-centric.** The host launcher keeps one persistent workstation container alive, starts a broker beside it, waits for the Herdr server, and mounts host roots plus runtime config into the container. Inside the control binary, `agent start/list/focus/resume/close/cleanup/reconcile` is already modeled, and registry records persist workspace/session metadata with file locking. Keep this lifecycle structure, but replace `WorktreePath` as the primary execution anchor with a more generic `CheckoutPath` or `ProjectMountPath`. (`/project/reference/herdr-sandbox-src-copy-28-07-2026/bin/llm:68-130, 147-220`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/cmd/herdr-sandbox/main.go:261-395`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/registry/registry.go:18-160`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/herdr/client.go:23-205`)

5. **Adapt: Ai Agents Sandbox already has the needed “no forced worktrees” escape hatch and the right three-mount container layout, but the implementation is too shell-heavy and too per-agent/per-project.** Its config seeds `AI_AGENTS_SANDBOX_WORKTREE_MODE=auto|off`, and exported `off` overrides the config as a rollback path; the README’s container layout is already the desired trusted-workstation shape: `/project/repo`, `/project/workspace`, `/project/reference`. Keep the direct-repo mode concept and mount contract, but not the giant shell launcher as the new control plane. (`/project/reference/ai-agents-sandbox-src-copy-28-07-2026/agents/base.sh:33-105, 124-132`; `/project/reference/ai-agents-sandbox-src-copy-28-07-2026/README.md:215-297`)

6. **Discard or heavily adapt: both Ai Agents Sandbox and Herdr assume managed worktrees are the default safety mechanism.** Ai Agents Sandbox defaults project mode to managed worktrees and documents primary/session worktree lifecycles; Herdr’s `worktree.Manager.Start` always resolves a base commit, creates a new worktree path, generates a branch, and records source/worktree host mirrors, while `forge exec` refuses to run outside a managed worktree. Those assumptions conflict directly with “no forced worktrees.” The extraction seam is to keep the registry and lifecycle APIs but swap the checkout strategy behind `start`. (`/project/reference/ai-agents-sandbox-src-copy-28-07-2026/README.md:249-273`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/worktree/worktree.go:31-104`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/cmd/herdr-sandbox/main.go:521-545`; `/project/reference/herdr-sandbox-src-copy-28-07-2026/internal/worktree/worktree_test.go:184-257`)

7. **Adapt selectively: Parley’s path-safe filesystem code is reusable, but not its current local execution architecture.** `pathsafe` rejects symlinks and root escapes; `worktrees.LocalManager` sanitizes path parts and branch names, verifies managed roots, and rejects symlinked parents; tests cover root containment and symlink rejection. Those helpers are good for any managed state directories, logs, artifacts, or optional checkout copies. But Parley’s executor still assumes per-attempt worktrees and containerized local Pi execution. (`/project/reference/parley-historical-prototype/internal/pathsafe/pathsafe.go:1-69`; `/project/reference/parley-historical-prototype/internal/worktrees/worktrees.go:1-120, 138-220`; `/project/reference/parley-historical-prototype/internal/pathsafe/pathsafe_test.go:11-46`; `/project/reference/parley-historical-prototype/internal/worktrees/worktrees_test.go:13-56`)

8. **Adapt selectively: Parley’s durable store and dispatcher are useful for audit/history and long-lived control, but its remote-runner story is not ready.** The main binary opens a persistent store, recovers queued attempts on startup, and runs a bounded dispatcher; the store persists SQLite-backed state under the data root and normalizes/repairs state at open time; tests cover recovery and non-spammy deferred dispatch. That evented, durable control-plane pattern is worth reusing for workstation audit/session history. But `ModeManager`/`ModeExecutor` are explicitly disabled until authenticated runner APIs exist, so Parley is not a reusable remote CLI/Hub foundation yet. (`/project/reference/parley-historical-prototype/cmd/parley/main.go:23-99`; `/project/reference/parley-historical-prototype/internal/store/store.go:18-44, 114-145`; `/project/reference/parley-historical-prototype/internal/dispatcher/dispatcher.go:25-164`; `/project/reference/parley-historical-prototype/internal/dispatcher/dispatcher_test.go:122-224`; `/project/reference/parley-historical-prototype/internal/config/config.go:67-116`; `/project/reference/parley-historical-prototype/internal/config/config_test.go:18-48`)

## Incompatible assumptions
- **Forced worktrees everywhere.** Herdr’s `agent start` and Parley’s local executor both assume a new managed checkout is the execution unit. Ai Agents Sandbox is the only one with a first-class direct-repo mode.
- **Open-ended repo discovery.** Herdr discovers repos recursively under one `/repos` root; the target calls for exactly three project mounts, so discovery should become explicit registration.
- **Per-agent isolation as product shape.** Ai Agents Sandbox is designed around separate agent containers and task/project modes; the target is one trusted workstation container.
- **Remote manager/executor is not real yet.** Parley names manager/executor modes and trusted LAN exposure, but both are deliberately disabled pending auth.
- **Forge CLI tied to managed checkout context.** Herdr’s `forge exec` resolves agent/project from the current managed worktree path, which breaks direct-repo sessions unless the lookup key changes.

## Smallest extraction seams
- **Herdr `internal/forge`** — lift almost whole. Replace config/project lookup and audit destination wiring only.
- **Herdr `internal/config.ValidateProjectID` + `internal/projects.Resolve`** — reuse as the mount registry validator for three configured project roots.
- **Herdr `internal/registry`** — keep file-locked record storage, but rename `WorktreePath` semantics to generic checkout/session paths.
- **Herdr `cmd/herdr-sandbox` agent lifecycle** — preserve `start/list/focus/resume/close/cleanup/reconcile` verbs; inject a checkout strategy interface so `direct` is valid beside `managed`.
- **Ai Agents Sandbox mount contract** — keep `/project/repo`, `/project/workspace`, `/project/reference`; reimplement in Go instead of inheriting the shell launcher.
- **Parley `pathsafe`** — reuse as a tiny utility package for any host-managed state, artifact, or optional-copy directories.
- **Parley dispatcher/store shape** — reuse conceptually for audit/event persistence, not the current task/attempt domain model whole cloth.

## Gaps
- I did not inspect Ai Agents Sandbox regression scripts under `agents/tests/` because the mounted repo path list was not enumerable with the available tools; the code and README were sufficient to confirm the worktree/mount design.
- I did not find a reusable authenticated remote CLI or Hub transport in current code; Parley and Herdr both stop short of that.
- Next step if this spike continues: define one checkout/session record schema that supports both `direct` and `managed` checkouts before any implementation extraction starts.

## Decision implications for this spike
- Build the spike around **Herdr’s broker + identity + path-validation core**.
- Keep **Ai Agents Sandbox’s direct-repo mode and three-mount contract** as a hard product requirement.
- Use **Parley only for durable state/audit patterns and tiny path-safety helpers**, not as the runtime architecture.
- Make **checkout strategy pluggable on day one**; otherwise the implementation will regress back into forced worktrees.
- Treat **remote CLI/Hub** as a separate authenticated design problem, not something already solved by Parley’s disabled modes.
